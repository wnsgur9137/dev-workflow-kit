# 리포트 포맷

상위: [[아키텍처]] · 관련: [[시크릿 처리]]

## 산출물
위치: `~/.local/share/dev-workflow-kit/security/reports/<run-id>/` (플러그인 폴더 밖 → [[ADR-006 플러그인 마켓플레이스 구조]])
```text
<run-id>/
├── raw/                 # 도구 원본 출력·실행 기록 (Claude 기본 열람 대상 아님)
│   ├── semgrep.json       # scan-code
│   ├── gitleaks-git.json  # scan-code, git 히스토리 (git 저장소일 때만)
│   ├── gitleaks-dir.json  # scan-code, 작업 트리
│   ├── osv.json           # scan-code
│   ├── checks.json        # scan-code, 스택 검사 (scripts/lib/checks.py)
│   ├── *.log              # 도구별 로그
│   ├── status.tsv         # 도구별 실행 결과 <도구>\t<ok|failed|skipped>\t<종료코드>\t<메모>
│   ├── profiles.tsv       # 감지된 프로파일과 하위 경로
│   ├── plan.tsv           # Semgrep 규칙셋·제외 경로 조립 결과
│   ├── warnings.txt       # 스캔 스크립트가 남긴 경고
│   ├── meta-in.json       # normalize.py 에 넘기는 메타
│   ├── mobsf.json         # scan-app (예정)
│   └── zap.json           # scan-web (예정)
├── findings.json        # 정규화된 전체 결과
├── summary.md           # Claude가 읽는 요약
└── meta.json            # 도구 버전, 이미지 digest, 대상, 시간
```

## 정규화 규칙
- **severity 통일**: `critical / high / medium / low / info`. 도구별 매핑표는 각 도구 노트에 둔다.
- **evidence 제한**: 최대 200자, 제어문자 제거, 시크릿 패턴 재마스킹. → [[시크릿 처리]]
- **신뢰하지 않는 텍스트 표시**: `summary.md`에서 도구가 추출한 문자열(APK 문자열, HTTP 응답 등)은 코드 블록 안에 넣고 "데이터"임을 명시한다. → [[위협 모델#T5 프롬프트 인젝션]]
  - 자유 텍스트 — 설명(Semgrep 메시지는 대상 코드가 메타변수로 치환된 값, OSV 요약에는 패키지 이름), 조치, 근거, 경고, 도구 오류 내용 — 는 ` ````text ` 코드 블록 안에만 둔다. 표에는 넣지 않는다.
  - 짧은 식별자 — 위치(경로·패키지), 규칙 ID, 프로파일 라벨, 참고 ID — 는 인라인 코드로 감싼다. 백틱·파이프는 치환하고 200자로 자른다.
  - 데이터 안의 백틱 3개 이상은 깨뜨려 코드 블록을 닫지 못하게 한다.
- **중복 제거**: `id` 기준.
- **베이스라인**: 이전 run과 비교해 신규/해결 표시 (P4, [[구현 계획]]).

## summary.md 구성
1. 메타: 대상, 시간, 프로파일, 도구 버전
2. 심각도별 개수
3. Critical/High 목록 — 제목(심각도·도구·규칙), 위치·프로파일·분류, 참고, id, 그리고 설명·조치·근거를 담은 코드 블록 하나
4. Medium 이하는 개수 + 상위 N개 표(번호·심각도·도구·위치·규칙)와, 같은 번호로 설명을 담은 코드 블록
5. 경고 — 코드 블록 안에 목록으로
6. 실행 중 오류·건너뛴 도구 — 표(도구·상태·종료코드)와 내용을 담은 코드 블록 (누락 은폐 금지)
