# ADR-008 스택별 프로파일

상위: [[보안 툴킷]] · 상세: [[스택 프로파일 개요]]

## 맥락
주력 스택이 iOS, Android, Flutter/React Native, Web, Server로 넓다(Q2, 2026-11-05 결정). 스택마다 취약점 유형, 규칙 언어, lockfile, 빌드 산출물, 확인해야 할 설정 파일이 다르다. 단일 규칙 묶음으로 전부 돌리면 오탐이 늘고, 스택 고유 위험(ATS, Manifest, `NEXT_PUBLIC_` 등)은 놓친다.

## 결정
- 스택별 **프로파일**(`$PLUGIN/profiles/<name>.yaml`)을 두고, 스캔은 감지된 프로파일의 합집합으로 실행한다.
- 도구 구성은 공통(Gitleaks, OSV-Scanner, Semgrep, MobSF, ZAP)을 유지하고, **새 도구는 추가하지 않는다** — 스택 고유 점검은 Semgrep 커스텀 규칙과 스크립트 검사로 구현한다.
- 설계 노트와 구현 PR을 **스택마다 분리**한다.

## 근거
- 도구를 늘리지 않아 공급망·네트워크 격리 설계([[ADR-004 네트워크 격리 강제]])를 그대로 유지
- 스택별 PR이라 리뷰 범위가 작고, 필요한 스택부터 쓸 수 있음
- 크로스플랫폼 앱은 네이티브 프로파일을 하위 경로에 재사용

## 결과 / 트레이드오프
- 스택마다 픽스처(의도적 취약 샘플)와 기준선이 필요 → [[검증 계획]]
- Semgrep 공식 규칙이 빈약한 언어(Swift, Dart)는 커스텀 규칙 비중이 커짐 → 해당 노트에 한계 명시
- Server의 Dockerfile 점검은 Semgrep `dockerfile` 규칙으로 하고, IaC(Terraform 등) 전용 도구는 범위 밖 ([[ADR-003 Trivy 제외]] 재검토 조건)
