# 업데이트 절차

상위: [[보안 툴킷]] · 관련: [[ADR-003 Trivy 제외]], [[ADR-006 플러그인 마켓플레이스 구조]], [[위협 모델#T3 공급망 침해]]

> [!important] 원칙
> 툴킷에서 **외부와 통신하는 유일한 경로**는 `$PLUGIN/scripts/update.sh`. 스캔 스크립트는 절대 다운로드하지 않는다.
> Claude는 `update.sh`를 실행할 권한이 없다 → 사용자가 직접 실행. [[Claude Code 권한 정책]]
> 경로 별칭: [[아키텍처#경로 표기]]

## 두 가지 업데이트

| 구분 | 누가 | 무엇을 | 방법 |
|---|---|---|---|
| **버전 고정 갱신** | 레포 관리자 | `images.lock`, `rules.lock`의 버전·digest·커밋 해시 | 레포에서 수정 → PR → 플러그인 새 버전 배포 |
| **데이터 다운로드** | 사용자 | lock에 고정된 이미지, 규칙, OSV DB | `/plugin` 업데이트 후 `update.sh` 실행 |

사용자는 lock 파일을 직접 바꾸지 않는다. 그래서 모든 사용자가 **검증된 같은 버전**을 쓴다.

## 사용자: `update.sh`
| 대상 | 저장 위치 | 주기(권장) |
|---|---|---|
| Docker 이미지 (`images.lock`의 digest 그대로 pull) | Docker 로컬 이미지 | 플러그인 업데이트 시 |
| Semgrep 규칙 (`rules.lock`의 커밋) | `$DATA/data/semgrep-rules/` | 플러그인 업데이트 시 |
| Nuclei 템플릿 (선택) | `$DATA/data/nuclei-templates/` | 플러그인 업데이트 시 |
| OSV 오프라인 DB | `$DATA/data/osv/` | **주 1회** (lock 대상 아님, 최신일수록 좋음) |

- OSV DB 갱신일은 `$DATA/data/osv/UPDATED_AT`에 기록 → 7일 초과 시 summary 경고
- pull한 이미지 digest가 `images.lock`과 다르면 중단
- 규칙은 설치 폴더의 `.commit`(1행 커밋, 2행 URL, 3행 paths)을 `rules.lock`과 비교한다. **커밋이나 paths 중 하나라도 다르면 다시 받는다.** 스캔은 둘이 다르면 summary에 "`update.sh --rules` 실행" 경고를 낸다
- 규칙 tarball 안전 추출(`scripts/lib/extract_rules.py`): 일반 파일만(링크·장치 파일 제외), 절대 경로·`..` 제외, **모든 항목의 최상위 폴더가 정확히 `<저장소 이름>-<commit>`이어야 한다**(다르거나 섞이면 기존 설치를 바꾸지 않고 실패). 이 확인은 응답이 요청한 커밋의 tarball인지만 본다 — codeload는 fork 네트워크에만 있는 커밋도 `<저장소 이름>-<commit>`으로 내려주므로(PR #21 리뷰에서 실측) **fork 커밋은 아래 관리자 절차 5단계에서 막는다**
- `rules.lock`의 이름은 `$DATA/data/<name>`이 되므로 `^[a-z0-9][a-z0-9_-]*$`만 허용하고, `osv`(OSV DB 폴더)는 거부한다
- 작업 폴더는 `mktemp -d`로 만든다 (강제 종료된 이전 실행의 잔여물과 섞이지 않게). 하루 지난 `.tmp-update*` 폴더는 시작할 때 지운다

## 관리자: lock 갱신 절차 (레포 PR)
1. 후보 버전 확인 → **공개 후 7일 이상 경과**한 릴리스만 (침해 버전이 발견·회수될 시간 확보)
2. 릴리스 노트·보안 공지 확인
3. 가능하면 서명/체크섬 검증 (cosign, 릴리스 checksums)
4. `docker pull <image>:<tag>` → digest 확인 → `images.lock` 갱신
5. `semgrep-rules` 등 규칙 저장소의 커밋 해시를 `rules.lock`에 갱신. 새 커밋이 **기본 브랜치에서 도달 가능한지** 확인한다 — `gh api repos/<owner>/<repo>/compare/<기본 브랜치>...<commit> --jq .status`가 `behind` 또는 `identical`이어야 한다 (fork 에만 있는 커밋 차단)
6. [[검증 계획]]의 회귀 테스트 실행 (기준선 비교, 네트워크 차단 확인). Docker 통합 테스트(`test_real_*`)를 **건너뛰지 않고** 돌린다 — Semgrep 이미지를 바꿀 때는 특히 내부 옵션 동작을 고정한 `test_real_semgrepignore_is_ignored_but_defaults_kept`가 통과해야 한다
7. PR로 병합 → 플러그인 버전 올림

> [!warning] 검증 필요
> - 각 도구의 서명 검증 지원 여부 (gitleaks/osv-scanner 릴리스 체크섬, 이미지 cosign 서명)
> - 플러그인 버전 관리 방식(`plugin.json`의 version)과 `/plugin` 업데이트 동작
