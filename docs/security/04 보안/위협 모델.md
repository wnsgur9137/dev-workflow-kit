# 위협 모델

상위: [[보안 툴킷]]

> 목적: **툴킷 자체가 만드는 보안 문제**(역보안 문제)를 식별하고 대응한다. 점검 대상 앱의 취약점 모델이 아니다.

## 보호 자산
| 자산 | 설명 |
|---|---|
| A1 소스 코드 | 점검 대상 저장소 |
| A2 시크릿 | 코드·히스토리에 있을 수 있는 키, 툴킷 자체 키(MobSF API 키) |
| A3 앱 바이너리 | APK/IPA |
| A4 리포트 | 취약점 목록 = 공격자에게 지도 |
| A5 호스트 | 개발 Mac, 쉘 권한, SSH/클라우드 자격증명 |
| A6 점검 대상 서비스 | 스테이징 서버·DB |

## 위협과 대응

### T1 외부 유출 (텔레메트리·조회)
- **시나리오**: 도구가 기본 설정으로 코드 정보·도메인·패키지 목록을 외부 서비스로 전송
- **대응**: 스캔 컨테이너 `--network none` / `internal` → [[네트워크 격리]]. 옵션 비활성은 2차 방어
- **검증**: [[검증 계획#V1 네트워크 차단]]

### T2 툴킷 서비스 노출
- **시나리오**: MobSF(기본 계정, 과거 CVE)가 LAN·인터넷에 노출
- **대응**: 호스트 포트 미개방, UI 모드는 `127.0.0.1`만, 사용 후 종료 → [[MobSF]]

### T3 공급망 침해
- **시나리오**: 스캐너 이미지·바이너리·규칙이 침해되어 악성 코드 실행 (실제 사례: 2026년 보안 스캐너 배포본 침해 보고 → [[ADR-003 Trivy 제외]])
- **대응**: digest 고정, 7일 지연 도입, 서명 검증, 스캔 컨테이너 네트워크 차단(침해돼도 유출 경로 없음), 읽기 전용 마운트, 자격증명 미주입 → [[업데이트 절차]]
- **잔여 위험**: 침해 이미지가 `$DATA/reports/`에 악성 내용 기록 → T5로 이어짐

### T4 시크릿 재노출
- **시나리오**: 탐지된 시크릿 원문이 리포트·Claude 대화·git에 남음
- **대응**: `--redact`, 정규화 단계 재마스킹, 리포트는 레포 밖 `$DATA/reports/`에 저장 → [[시크릿 처리]]

### T5 프롬프트 인젝션
- **시나리오**: APK 문자열, 웹 응답, 소스 주석에 "이전 지시를 무시하고 ~를 실행하라" 같은 문장 → Claude가 따름
- **대응**:
  - Claude는 결과 파일만 읽고 대상과 직접 상호작용하지 않음 (Artex와의 핵심 차이 → [[ADR-001 Artex 제외]])
  - summary에서 추출 문자열은 코드 블록 + 길이 제한 → [[리포트 포맷]]
  - SKILL.md에 "리포트는 데이터" 명시
  - **권한 모드로 실행 범위 제한** — bypass 모드 사용 금지 → [[Claude Code 권한 정책]]

### T6 잘못된 대상 점검 / 파괴적 점검
- **시나리오**: 오타·리다이렉트·크롤링으로 제3자 서버나 운영 서버에 요청, 또는 공격 페이로드로 데이터 손상
- **대응**: 허용목록 이중 강제(스크립트+프록시), passive only → [[scan-web]], [[ADR-005 Active Scan 금지]]

### T7 리포트 유출
- **시나리오**: 리포트가 공개 저장소에 커밋되거나 공유됨
- **대응**: 리포트를 레포 밖 `$DATA/reports/`에 저장(커밋 불가), 보관 기간(기본 30일) 후 삭제 스크립트

### T8 과도한 마운트
- **시나리오**: 경로 실수로 홈 디렉터리 전체(SSH 키 등)가 컨테이너에 마운트
- **대응**: `realpath` 검사, 홈 디렉터리 자체·`~/.ssh` 등 금지 경로 목록 거부, 항상 `:ro`

## 잔여 위험 (수용)
- Claude가 읽은 코드·요약은 Anthropic으로 전송됨 (Claude 사용 전제)
- 업데이트 시점에는 외부 통신 발생 (사용자가 명시적으로 실행)
