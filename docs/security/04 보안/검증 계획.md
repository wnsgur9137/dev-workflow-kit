# 검증 계획

상위: [[보안 툴킷]] · 관련: [[구현 계획]], [[업데이트 절차]]

## V1 네트워크 차단
| 테스트 | 방법 | 기대 결과 |
|---|---|---|
| N0 컨테이너 | 각 이미지에서 `curl https://example.com` 또는 동등 명령 | 실패 |
| N1 MobSF | mobsf 컨테이너에서 외부 접속 시도 | 실패 — `test_real_n1_mobsf_is_internal_only`(IP·DNS 차단, 내부 이름은 풀림) |
| N1 호스트 노출 | 호스트에서 `curl localhost:8000`, `PortBindings`·`NetworkSettings.Ports`, 네트워크 `Internal` | 연결 없음 — 같은 테스트 |
| N2 허용목록 외 | ZAP 컨테이너에서 허용목록 밖 URL 요청 | 프록시 403 + 로그 — `test_real_n2_proxy_enforces_allowlist_and_blocks_bypass`(같은 호스트 다른 포트·외부 도메인), 스캔마다 `scan-web.sh` 격리 확인 |
| N2 프록시 우회 | 프록시 설정 없이 직접 요청 | 실패 — 같은 테스트(대상 호스트·외부 IP 직접 연결) |
| 실측 | **LuLu**(무료 macOS 방화벽)로 스캔 1회 전체 동안 Docker 외부 연결 기록 | 업데이트 외 연결 없음 |

> macOS의 Docker 런타임은 VM을 경유하므로 LuLu에는 컨테이너가 아니라 VM 프로세스(Docker Desktop은 Docker 프로세스, Colima는 Lima·VZ 프로세스)로 보인다. 컨테이너 단위 확인은 위 테스트로, 전체 확인은 LuLu로 이중 검증.

### LuLu 실측 절차 (사람이 수행 — P4)
자동 테스트는 컨테이너 단위로 격리를 확인한다. LuLu 실측은 "툴킷 전체가 스캔 중에 밖으로 나가지 않는다"를 호스트에서 한 번 더 본다. GUI 방화벽이라 사람이 지켜봐야 한다.

> [!warning] 이 실측이 볼 수 있는 범위
> macOS 런타임은 VM 을 거친다. LuLu 가 VM 의 연결을 볼 수 있는지는 네트워크 방식에 달려 있다. 호스트 프로세스가 소켓을 여는 사용자 모드(gvproxy·hostagent·vpnkit 등)는 보이지만, 커널에서 NAT 하는 방식(vmnet·vzNAT·socket_vmnet)은 안 보일 수 있다. 그래서 **양성 대조군**(일부러 만든 외부 연결)이 경고로 보이는지 먼저 확인하고, 안 보이면 그 구성의 실측은 무효로 본다. 루프백(호스트 127.0.0.1)과 시스템 리졸버(mDNSResponder)를 거치는 DNS 는 이 실측의 범위 밖이다 — 컨테이너의 DNS 차단은 자동 테스트(N0·N1·N2)가 본다.

1. **먼저 `update.sh` 를 끝낸다** (이미지·규칙·OSV DB·egress-proxy 빌드). 실측 중에 돌면 정상적인 외부 연결이 섞이고, 경고에서 차단을 누르면 업데이트가 실패한다
2. **구성 기록**: 런타임과 네트워크 방식 — Colima 면 `colima status`·`colima list` 와 `~/.colima/default/colima.yaml` 의 `vmType`·`network`, Docker Desktop 이면 버전과 네트워크 설정
3. **LuLu 설정**: Passive 모드 끔, "Apple 프로그램 허용"·"설치된 앱 허용" 끔(설치할 때 고르는 옵션 — 켜져 있으면 Apple 서명 VM 프로세스와 Docker·Colima 가 묻지 않고 허용된다). 기존 규칙 중 Docker·Colima(Lima·VZ·`com.docker.*`)·`com.apple.Virtualization.*` 를 허용한 항목은 잠시 끈다(지우지 말고 끈 목록을 적어 둔다)
4. **기준선**: 스캔 없이 런타임만 켠 상태로 5분 동안 보이는 연결을 적는다(시간 동기화, Docker Desktop 의 업데이트 확인·텔레메트리 등). 이후 판정에서 이것과 구분한다
5. **양성 대조군**: 이미 받은 이미지로 외부 연결을 일부러 한 번 만든다 — `docker run --rm alpine@<images.lock 의 egress-proxy-base digest> wget -q -O- https://example.com`. **LuLu 경고가 뜨는지 확인**한다(뜨면 차단해도 된다). 뜨지 않으면 이 구성에서는 실측이 무효다 — 구성을 기록하고 다른 네트워크 방식으로 다시 한다
6. **스캔별 기록** — 각 스캔을 하나씩 실행하며 LuLu 경고·로그를 적는다
   - `scan-code.sh <작은 테스트 저장소>` → 예상: 외부 연결 없음
   - `scan-app.sh <테스트 APK>` → 예상: 외부 연결 없음
   - `scan-web.sh http://host.docker.internal:<포트>/` (허용목록에 그 출처를 넣음) → 예상: 인터넷 주소로 가는 연결 없음(호스트 대상 서버로 가는 연결은 루프백이라 보이지 않을 수 있다)
7. **판정**
   - 통과: 양성 대조군 경고를 확인했고, 스캔 중 기준선 밖의 연결 시도가 0건
   - 실패: 기준선 밖의 연결이 있음. 경고는 **허용하지 말고 차단**하고, 프로세스·목적지·시각과 그때 돌던 스캔을 적어 이슈로 남긴다. 그 스캔의 `run.log`·summary 의 "프록시가 막은 요청" 을 함께 첨부한다(질의값은 가려져 있다)
   - 판정 불가: 양성 대조군이 보이지 않음
8. **복구**: 실측 중 만든 차단 규칙을 지우고(다음 `update.sh` 를 막지 않게), 3단계에서 끈 허용 규칙·설정을 되돌린다
9. **결과 기록**: 날짜, 2단계의 구성, 플러그인 버전, 스캔별 결과를 [[구현 계획]] P4 마무리 절의 실측 항목 아래에 적는다

## V2 탐지 정확도 (회귀 기준선)
| 대상 | 내용 | 기대 |
|---|---|---|
| 시크릿 픽스처 | 가짜 AWS 키·GitHub 토큰 형식 문자열을 커밋 후 삭제한 테스트 저장소 | Gitleaks git 모드가 히스토리에서 탐지, 원문 미노출 |
| SAST 픽스처 | 의도적 XSS/SQLi 코드 몇 줄 | Semgrep 탐지 |
| SCA 픽스처 | 알려진 취약 버전 고정 lockfile | OSV 탐지 |
| 모바일 | `debuggable`·cleartext 켠 내 테스트 빌드 — `tests/fixtures/app/`를 MobSF 이미지 안의 apktool·bundletool(APK·AAB)과 Xcode clang(IPA)으로 네트워크 없이 빌드 | MobSF·Gitleaks 탐지 — `tests/baseline/app-android.json`·`app-ios.json` |
| 웹 | 보안 헤더 없는 로컬 테스트 서버 | ZAP 탐지 |

결과를 `tests/baseline/*.json`으로 저장 → 업데이트 후 비교.
