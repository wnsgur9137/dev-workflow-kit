# 스택 프로파일 개요

상위: [[보안 툴킷]] · 결정: [[ADR-008 스택별 프로파일]]

> [!summary]
> 점검 도구는 공통이지만 **무엇을, 어떤 규칙으로, 어떤 산출물에서** 찾을지는 스택마다 다르다. 스택마다 **프로파일**을 두고, `/security:scan-*`는 대상 저장소의 스택을 감지해 해당 프로파일을 합쳐 실행한다.

## 지원 스택

| 프로파일 | 대상 | 설계 노트 |
|---|---|---|
| `ios` | Swift / Objective-C 앱 | [[iOS]] |
| `android` | Kotlin / Java 앱 | [[Android]] |
| `flutter` | Flutter (Dart) 앱 | [[Flutter·React Native]] |
| `react-native` | React Native (JS/TS) 앱 | [[Flutter·React Native]] |
| `web` | JS/TS 웹 (Node, React, Next.js) | [[Web]] |
| `server` | Python / Go / Java / Node 서버 | [[Server]] |

## 공통 기반 (모든 프로파일)
| 영역 | 도구 | 공통 동작 |
|---|---|---|
| 시크릿 | [[Gitleaks]] | git 히스토리 + 작업 트리, `--redact` |
| 의존성 | [[OSV-Scanner]] | 프로파일이 지정한 lockfile 대상 |
| SAST 공통 | [[Semgrep]] | `generic` 시크릿·위험 패턴 규칙 + 프로파일별 언어 규칙 |
| 리포트 | — | [[리포트 포맷]]에 `profile` 필드 추가 |

## 프로파일 정의 형식 (`$PLUGIN/profiles/<name>.yaml`)
```yaml
name: android
detect:                     # 항목 중 하나라도 맞으면 이 스택으로 판정
  - "**/AndroidManifest.xml"            # 형식 1: 파일 glob (근거 파일의 폴더가 하위 프로젝트)
  # 형식 2: 의존성 조건 — 매니페스트 파일을 파싱해 의존성 이름으로 판정
  # - { file: "**/package.json", has_dependency: [react-native] }
  # 형식 3: glob + root_markers — 근거 파일에서 위로 올라가 이 파일이 있는 가장 가까운 폴더를 하위 프로젝트로 잡는다
  # - { glob: "**/AndroidManifest.xml", root_markers: [settings.gradle, settings.gradle.kts] }
exclude_if:                 # 같은 하위 프로젝트에서 다른 프로파일이 감지되면 그 경로에서만 제외 (선택)
  - react-native
exclude_paths:              # 스캔에서 제외 (빌드 산출물 등)
  - "**/build/**"
semgrep:
  rulesets: [kotlin, java, generic]   # $DATA/data/semgrep-rules/ 하위 디렉터리
  custom: [android]                   # $PLUGIN/rules/custom/android/
sca:
  lockfiles: ["**/gradle.lockfile", "**/gradle/verification-metadata.xml"]
  missing_lockfile_hint: "Gradle 의존성 잠금(dependencyLocking) 활성화 권장"
  # unsupported_lockfiles: ["**/Podfile.lock"]   # OSV-Scanner 가 읽지 못하는 lockfile — 있으면 "점검되지 않음" 경고 (선택)
artifact:                   # /security:scan-app 대상 산출물
  types: [apk, aab]
  analyzer: mobsf
checklist: android          # summary에 붙는 스택별 수동 확인 항목
```

## 감지 규칙
0. `detect` 항목은 **파일 glob**, **의존성 조건**(`{file, has_dependency}`), **glob + 루트 표식**(`{glob, root_markers}`) 세 형식만 쓴다. 루트 표식은 그 항목에만 적용된다(다른 항목의 하위 프로젝트를 끌어올리지 않음, PR #18 리뷰 W5). 의존성 조건은 `package.json`(dependencies·devDependencies), `pubspec.yaml`, `pyproject.toml`, `go.mod`, `pom.xml`·`build.gradle*`에서 이름을 찾는다.
1. `/security:scan-code <경로>`는 `detect` 패턴으로 프로파일을 **모두** 고른다 (모노레포·크로스플랫폼은 여러 개).
2. `--profile=<name,...>`으로 강제 지정 가능. 감지 결과가 0개면 공통 기반만 실행하고 summary에 표시.
3. 크로스플랫폼 앱은 하위 네이티브 폴더도 감지된다 (Flutter의 `ios/`·`android/`) → 네이티브 프로파일을 **해당 하위 경로에만** 적용 ([[Flutter·React Native#네이티브 하위 프로젝트]]).
4. `exclude_if`는 **하위 프로젝트 단위**(감지 근거가 된 매니페스트 파일의 디렉터리)로 적용한다. 모노레포에서 `apps/mobile`(RN)과 `apps/web`(React)이 함께 있으면 `apps/mobile`에만 web이 제외된다.
5. 감지된 프로파일 목록은 `meta.json`과 summary 머리에 기록.
6. **하위 프로젝트 경로**는 감지 근거 파일의 폴더(번들형 `.xcodeproj` 등은 그 부모)이고, 형식 3이면 `root_markers` 파일이 있는 가장 가까운 상위 폴더다. 같은 프로파일이 상위·하위 경로에서 모두 감지되면 상위 경로 하나로 합치되, 그 안에서 `exclude_if` 대상이 감지된 더 깊은 경로는 **제외 경로**로 남긴다(예: 루트 `package.json`에 react가 있는 모노레포의 web(`.`)은 RN 앱 `apps/mobile`을 제외). 감지기 출력(TSV)의 셋째 열이 제외 경로다.
7. 감지할 때 `node_modules`, `Pods`, `build`, `.dart_tool`, `.git` 등 의존성·산출물 폴더로는 내려가지 않고, 심볼릭 링크 폴더도 따라가지 않는다.
8. `exclude_paths`는 **그 프로파일이 감지된 하위 경로 안에서만** 스캔 제외로 쓴다. 루트(`.`)에서 감지된 프로파일은 모든 깊이에(가운데 `/`가 있는 패턴은 gitignore 문법상 루트에 고정되므로 `**/`를 붙인다), 하위 경로에서 감지된 프로파일은 `<하위 경로>/**/<패턴>`으로 고정한다(예: Flutter의 `ios/` 프로파일의 `**/macos/**` → `ios/**/macos` — 루트의 `macos/` 데스크톱 러너는 점검). 하위 경로 이름의 glob 특수문자는 이스케이프한다. Semgrep 1.182.0 `--exclude`(gitignore 문법)로 실측 확인하고 통합 테스트(`test_real_exclude_paths_are_scoped_to_profile_root`)로 고정했다 (PR #19 리뷰 QUESTION, PR #22 리뷰).
   - 소스일 가능성이 거의 없는 `Pods`·`DerivedData`·`.gradle`·`.dart_tool`은 프로파일과 무관하게 **전역 제외**한다. 하위 경로로 한정하면 어느 프로파일에도 속하지 않는 경로(Flutter의 `macos/Pods`)가 남기 때문이다. `node_modules`·`build`·`dist`·`vendor`·`.venv`는 Semgrep 기본 무시 목록이 이미 뺀다.
   - 한계: 루트에서 감지된 프로파일의 제외는 그 아래 다른 하위 프로젝트에도 적용된다(Semgrep `--exclude`로 "어디 빼고"를 표현할 수 없음). 감지기 출력의 셋째 열(제외 하위 경로)은 프로파일 귀속에만 쓰고 스캔 제외 범위에는 쓰지 않는다.
   - 참고: Semgrep 1.182.0은 `.semgrepignore`가 없으면 기본 무시 목록으로 `tests/` 폴더도 점검하지 않는다 (PR #22 리뷰 관찰, 별도 검토 대상).

> [!info] 구현 (P0)
> 로더·감지기: `$PLUGIN/scripts/lib/profiles.py` (표준 라이브러리만 사용 — 프로파일 파일은 블록 매핑·리스트, 흐름 `[ ]`·`{ }`, 따옴표 문자열, 주석만 쓰는 YAML 부분집합). 알 수 없는 키·형식 오류는 로드 시 거부한다. 테스트: `$PLUGIN/tests/test_profiles.py` + `tests/fixtures/detect/<스택>/`

## 스택별 차이 한눈에

| | iOS | Android | Flutter | React Native | Web | Server |

| Semgrep 언어 | swift | kotlin, java | dart | javascript, typescript | javascript, typescript | python, go, java, javascript |
| lockfile | `Package.resolved`, `Podfile.lock` | `gradle.lockfile` | `pubspec.lock` | `package-lock.json` 등 | `package-lock.json` 등 | `poetry.lock`, `go.sum`, `pom.xml` 등 |
| `/security:scan-app` | IPA (MobSF) | APK·AAB (MobSF) | IPA·APK (MobSF) | IPA·APK (MobSF) | — | — |
| `/security:scan-web` | — | — | — | — | ZAP baseline | ZAP baseline (API 엔드포인트) |
| 고유 점검 | ATS, Keychain, Info.plist | Manifest, network_security_config | `--obfuscate`, `--dart-define` 노출 | JS 번들 내 키, Hermes | `NEXT_PUBLIC_` 노출, 보안 헤더 | Dockerfile, 설정 파일, 디버그 모드 |
