# ADR-006 플러그인 마켓플레이스 구조

상위: [[Home]] · 계획: [[레포 통합 계획]]

## 맥락
기존 워크플로 커맨드는 파일을 `~/.claude/commands`, `~/.claude/templates`에 복사해 설치했다. 이 방식에서 레포와 로컬 설치본이 어긋났다 (`pipeline` 로컬에만 존재, `apply-review` 레포만 최신, `create-pr` 양쪽 분기). 보안 툴킷은 스크립트·Docker 파일까지 배포해야 한다.

## 결정
레포를 Claude Code **플러그인 마켓플레이스**로 만들고 플러그인 2개로 나눈다.

```text
dev-workflow-kit/
├── .claude-plugin/marketplace.json
├── plugins/
│   ├── workflow/   # commit, create-pr, pr-review, apply-review, pipeline + templates
│   └── security/   # scan-code, scan-app, scan-web 스킬 + scripts, docker, rules lock
├── docs/           # Obsidian vault
└── examples/       # mcp.json.example
```

## 근거
- 설치·업데이트가 `/plugin` 명령 하나로 통일 → 레포와 로컬 불일치 재발 방지
- 필요한 플러그인만 설치 가능 (보안 툴킷 없이 workflow만 등)
- 스크립트·설정 파일을 스킬과 함께 배포 가능

## 결과 / 트레이드오프
- 커맨드의 템플릿 경로를 `${CLAUDE_PLUGIN_ROOT}` 기준으로 수정해야 함
- **플러그인 폴더는 업데이트 시 교체될 수 있음** → 사용자 데이터는 플러그인 밖에 둔다

| 데이터 | 위치 |
|---|---|
| 보안 리포트 | `~/.local/share/dev-workflow-kit/security/reports/` |
| OSV DB, 받은 Semgrep 규칙·Nuclei 템플릿 | `~/.local/share/dev-workflow-kit/security/data/` |
| `.env` (MobSF API 키), `targets.allowlist` | `~/.config/dev-workflow-kit/security/` |
| 리뷰 이력·외부 레포 캐시 | 기존 위치 유지 (`~/.claude/review-history`, `~/.claude/repo-cache`) |
| 버전 고정 파일 (`images.lock`, `rules.lock`) | 플러그인 내부 (레포에서 관리) |

- 플러그인은 권한(permissions)을 스스로 설정하지 못함 → 예시 설정을 사용자가 `~/.claude/settings.json`에 추가 → [[Claude Code 권한 정책]]
- 로컬 설치본은 백업 후 제거 (이름 충돌 방지)

> [!warning] 검증 필요
> - 플러그인 커맨드/스킬 호출 이름 (`/commit` 그대로인지 `/workflow:commit` 형태인지)
> - 스킬 frontmatter `allowed-tools`에서 `${CLAUDE_PLUGIN_ROOT}` 경로 사용 가능 여부
> - 플러그인 이름 `workflow`, `security`가 다른 마켓플레이스와 충돌 시 동작
