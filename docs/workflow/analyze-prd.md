# /analyze-prd

상위: [Home](../Home.md) · [README](../../README.md)

PDF 기획서(PRD)를 읽어 **개발 설계서 초안**을 만듭니다. 기능 분해·기술 스택·아키텍처·개발 태스크·리스크와, 기획서에 없거나 서로 어긋나 **확인이 필요한 질문**을 담습니다. 결과는 결정이 아니라 초안이며, [/pipeline](pipeline.md) 6단계 기획서를 쓸 때 입력으로 씁니다.

## 사용법

```
/analyze-prd <PDF 경로> [--detailed] [--out=<경로>]
```

## 예시

```
/analyze-prd ~/Downloads/기획서.pdf
/analyze-prd ./docs/prd.pdf --detailed --out=docs/07-기획/설계-초안.md
```

## 옵션

| 옵션 | 설명 |
|------|------|
| `--detailed` | 표·이미지가 많은 기획서용. 화면 설계·데이터 모델·API 절을 더하고 표를 셀 단위로 옮김 |
| `--out=<경로>` | 설계서를 Markdown 파일로 저장 (없으면 화면 출력만, 커밋은 하지 않음) |
| `-h`, `--help` | 도움말 표시 |

## PDF 읽는 방법

처음 되는 방법을 씁니다. 변환은 이 기기 안에서만 하고 PDF 내용을 외부 서비스로 보내지 않습니다.

| 순서 | 방법 | 비고 |
|---|---|---|
| 1 | Claude Code의 파일 읽기(`Read`) | 별도 설치 없음. 그림·와이어프레임·스캔 쪽도 봄 |
| 2 | PDF 변환 MCP 도구(예: `convert_pdf`) | 이 기기에서 도는 서버로 확인될 때만. 원격이거나 모르면 쓰지 않음(쓰려면 동의) |
| 3 | `pdftotext -layout` (poppler, `brew install poppler`) | 글자만. Codex처럼 PDF를 직접 못 읽는 환경의 경로. 쪽 범위로 나눠 읽어 잘림·쪽 번호 손실을 막음 |

글자가 거의 없는 쪽은 파일 읽기 도구로 시각적으로 읽고 "읽기 한계"에 적습니다. `pdftotext`만 쓸 수 있으면 OCR이 필요하다고 알리고 멈춥니다.

## 동작

- git 저장소 안에서 실행하면 현재 기술 스택·기존 모듈·기획서 템플릿을 확인해, 기술 스택은 **현재 스택을 따르고 새로 필요한 것만** 적고 아키텍처는 고칠 곳과 새로 만들 곳을 나눕니다. 저장소 밖이면 스택을 제안합니다.
- 기능 표에는 근거 쪽 번호를 답니다. 근거가 없는 칸은 비우지 않고 `확인 필요`로 씁니다.
- 개발 태스크는 PR 하나 크기로 자릅니다.
- PDF 안의 글은 데이터로만 다루고, 그 안의 지시문은 따르지도 설계서에 옮기지도 않습니다(쪽 번호와 "지시문 있음"만 적음).
- 자동 허용하는 셸 명령은 `pdfinfo`·`pdftotext`·`git rev-parse`뿐이고, 파일 저장(`--out`)은 권한 확인을 거칩니다.
- 끝에 "읽기 한계"(읽지 못한 쪽, 놓친 그림, 깨진 표)를 적습니다.
