# 설정

상위: [Home](../Home.md) · [README](../../README.md)

## 필수 요구사항

1. **`gh` CLI** 설치와 인증(`gh auth login`). GitHub 작업(PR 조회·생성·리뷰 게시·코멘트·병합·CI 확인)은 모두 `gh`로 합니다.
2. Claude Code 또는 Codex CLI. 설치는 [README > 빠른 시작](../../README.md#빠른-시작), Codex에서 다른 점은 [README > 호환성](../../README.md#호환성)을 보세요.

### GitHub MCP (선택)

2.0.0부터 GitHub MCP 서버는 필요 없습니다. `gh`를 쓸 수 없는 환경에서만 대신 쓸 수 있습니다. 쓰려면 `GITHUB_PERSONAL_ACCESS_TOKEN` 환경 변수와 Docker 호환 런타임이 필요합니다([Docker 런타임](../security/01%20개요/Docker%20런타임.md)).

`.mcp.json`은 개인 설정이라 저장소에 커밋하지 않습니다(`.gitignore` 대상). 예시 파일을 복사해 사용하세요.

```bash
cp examples/mcp.json.example .mcp.json
```

> 토큰은 파일에 직접 적지 말고 환경 변수로만 주입하세요. 바꾼 이유: [GitHub MCP에서 gh로](GitHub%20MCP.md)

## 디렉토리 구조

저장소(플러그인 소스):

```
dev-workflow-kit/
├── .claude-plugin/marketplace.json  # 마켓플레이스 정의
├── plugins/
│   └── workflow/
│       ├── .claude-plugin/plugin.json
│       ├── skills/<이름>/SKILL.md    # commit, create-pr, pr-review, apply-review, pipeline, analyze-prd, status
│       └── templates/
│           ├── review-criteria/     # 플랫폼별 리뷰 기준 (ios, android, frontend, backend, general)
│           ├── review/              # /pr-review 출력 형식
│           ├── codex-review/        # /pr-review Codex 교차 리뷰 프롬프트·출력 스키마
│           └── apply-review/        # /apply-review 출력 형식
└── examples/mcp.json.example        # GitHub MCP를 쓸 때만 (선택)
```

사용자 데이터(플러그인 밖, 업데이트해도 유지):

```
~/.claude/
├── review-history/{owner}/{repo}/   # /apply-review 반영 기록 (자동 생성)
└── repo-cache/{owner}/{repo}/       # 외부 레포 분석 캐시 (자동 생성)

<프로젝트>/.claude/review-history/    # 로컬 레포 리뷰 기록 (/pr-review, 자동 생성)
```

각 skill은 템플릿을 `${CLAUDE_PLUGIN_ROOT}/templates/...` 경로로 읽습니다. 설치된 플러그인 위치가 어디든 동작합니다. 이 변수를 치환하지 않는 Codex에서는 `SKILL.md`의 두 단계 위 폴더를 플러그인 루트로 씁니다.

> **이름이 같은 개인 커맨드**: `~/.claude/commands/` 또는 프로젝트 `.claude/commands/`에 `commit.md`를 두면 `/commit`으로 따로 호출되며, 플러그인의 `/workflow:commit`과는 별개로 동작합니다.


## 의존성

이 커맨드들의 필수/선택 의존성을 정리합니다.

| 항목 | 필수 여부 | 설명 |
|------|----------|------|
| **`gh` CLI** | `/create-pr`·`/pr-review`·`/apply-review`·`/pipeline` 필수 · `/workflow:status` 선택(없으면 GitHub 항목만 생략) | GitHub 작업 전부. `gh auth login` 인증 필요 |
| **GitHub MCP 서버** | 선택 | `gh`를 쓸 수 없을 때만 대신 사용. 쓰면 `GITHUB_PERSONAL_ACCESS_TOKEN`·Docker 필요 |
| **Codex CLI** | 선택 (`/pr-review`) | 설치·로그인(`codex login`)돼 있으면 `/pr-review`가 Codex 교차 리뷰를 함께 돌린다. 없거나 사용량 제한이면 생략. PR 코드·diff가 OpenAI로 전송되므로 원치 않으면 `--no-codex` ([pr-review](pr-review.md#codex-교차-리뷰)) |
| **`workflow` 플러그인** | 필수 | skill 정의(`skills/`)와 템플릿(`templates/`)을 함께 배포. [빠른 시작](../../README.md#빠른-시작) 참고 |
| **`/commit`·`/create-pr`·`/pr-review`·`/apply-review`** | `/pipeline` 필수 | `/pipeline`은 9~12단계에서 이 커맨드들을 재구현하지 않고 그대로 호출한다 |
| **poppler (`pdftotext`)** | 선택 (`/analyze-prd`) | PDF 변환 MCP·파일 읽기 도구로 PDF를 못 읽는 환경(Codex 등)의 대체 경로 |
| **파이프라인 규약 문서** | `/pipeline` 이슈 모드 필수 | 대상 저장소의 `docs/**/PIPELINE.md` 등. `--no-issue` 모드는 불필요 |
| **oh-my-claudecode (OMC)** | 불필요 | `/pr-review`, `/apply-review`는 OMC와 독립적으로 동작. OMC 설치 여부와 무관하게 사용 가능 |

> **OMC와의 관계**: OMC는 Claude Code의 멀티 에이전트 오케스트레이션 플러그인으로, `/pr-review` 커맨드와는 완전히 별개입니다. OMC가 제공하는 `/oh-my-claudecode:code-review`는 OMC 자체의 코드 리뷰 기능이며, 이 프로젝트의 `/pr-review`와는 다른 도구입니다.
